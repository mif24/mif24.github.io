什么是AI_agent

前言

本笔记主要学习于《深入理解 AI Agent》

一些简单概念可能使用到：

  • KV Cache：KV Cache（键值缓存）用显存空间换计算时间，避免在逐字生成（Generation）过程中对历史已处理过的 Token 重复执行矩阵乘法计算。
  • 缓存命中（Cache Hit）：当 Agent 或底层大模型（LLM）发起一次计算、检索、推理或工具调用请求时，系统发现相同或语义相似的输入/状态在之前已经处理过，可以直接复用已保存的结果，而无需重新执行耗时的计算或调用。

核心公式：Agent = LLM + 上下文 + 工具

三者缺一不可。

  • LLM：大语言模型，相当于整个Agent的大脑。
  • 上下文：记忆，指令等，相当于整个Agent的眼睛。Agent的上下文窗口即为当前AI所能看到、记忆的一切。
  • 工具：代码，执行等，相当于整个Agent的手脚。

工具

Agent 的工具：

  1. 感知工具
    • 多模态视觉感知工具 (Visual Perception)
    • 音频与语音感知工具 (Auditory Perception)
    • 数字环境与GUI界面感知工具 (Digital & GUI Perception)，注：在操作系统、浏览器或独立软件中充当Agent的”屏幕查看器”，支持自动化操作（OS Agent / Web Agent）
    • 信息检索与动态知识感知工具 (External Knowledge Perception)
  2. 执行工具：代码执行、文件操作、系统命令、外部 API 调用
  3. 协作工具：在关键决策点请求人类确认，让 Agent 与其他 Agent 分工合作。

工具的使用质量和数量决定了Agent的能力上限，清晰的接口，工具调用能让AI发挥全部的能力。MCP（Model Context Protocol，模型上下文协议）让工具的接入变得和安装插件一样，例如金融消息查看可以安装iFinD、通达信等。

Agent 的学习机制

Agent 的行为如何发生改变？

  1. 任务内适应：当前上下文（实例、状态、检索结果）
  2. 外部制品更新：知识·指令·程序（文档、Prompt（提示词）、skill、Harness）
  3. 模型参数更新：模型权重：SFT · 偏好训练 · RL

把事实和经验整理为知识文档，把可语言化的策略写进Prompt 或 Skill，把确定性流程与约束写成程序和 Harness。

上下文

上下文：决定 Agent 能力上限的关键（更丰富的上下文，更准确、更高信噪比的上下文工程与状态感知）

以下五个部分构成：

  1. Prompt：定义AI的身份、权限和行为准则。系统提示词中还会包含跨会话保存的用户记忆（用户偏好、历史行为、背景设定等个性化信息）和动态注入的环境状态。
  2. 工具定义
  3. 用户消息：用户消息中还可能包含通过 RAG（检索增强生成，Retrieval-Augmented Generation）动态检索引入的外部知识——覆盖训练数据截止后的信息或私有领域知识。
  4. 模型回复：模型生成的回复，最多包含三个部分：
    1. 思维链
    2. 文本内容
    3. 工具调用请求
  5. 工具执行结果

前两项（系统提示词 + 工具定义）是静态前缀，后三项（用户消息 + 模型回复 + 工具执行结果）的轨迹是随交互不断增长的动态消息历史。这五个部分共同构成了 LLM 每次推理时的上下文。

上半部分（System Prompt + Tool Definitions）在整个对话过程中保持不变，下半部分（对话历史）随着交互的进行不断增长

三条核心结论：

  1. 系统提示词和工具定义一旦确定就不要改。任何改动，哪怕多一个空格，都会导致缓存全部失效，延迟成倍增加、成本上升（具体幅度视模型与配置而定）。
  2. 动态信息永远追加到末尾——时间戳、用户状态等变化的内容，作为新消息追加到对话末尾，而不是修改已有的系统提示词。
  3. 使用标准 API 格式，不要自行拼接消息：结构化消息会被 Chat Template 翻译成模型训练时见过的固定token 序列；自行用字符串拼成 “USER: … ASSISTANT: …” 的根本问题是偏离了这种训练格式，会削弱模型的多步思考能力。至于缓存——它只认 token 字节序列，只要拼出的前缀字节级稳定，照样能命中；但若拼接方式不稳定（如每次向前缀注入动态内容），缓存也会随之失效。

Harness 五个功能的核心原则

  1. 上下文：信息充分性
    • 信息充分性：让 Agent 在每个决策点都基于足够的信息判断
    • 系统提示词、知识库、Agent 状态栏、Sidecar 旁路查询
  2. 工具：接口清晰
    • 接口清晰：工具命名直观、参数有例子、边界有说明
    • MCP 工具、代码解释器、搜索工具
  3. 约束：故障安全默认值
    • 故障安全默认值：所有能力默认关闭，必须显式开放
    • 需要用户授权才能执行
  4. 验证：输入隔离
    • 输入隔离：安全检查只看结构化数据（如工具返回的JSON 字段），而不是模型自由生成的文本（因为攻击者可能通过提示注入操纵模型输出）
    • Linter 检查、类型系统、工具调用结果校验
  5. 纠正
    • 在确认无法恢复之前，不暴露中间态（例如工具调用失败时先静默重试，不将半成品结果展示给用户）
    • 静默重试、接续生成、连续失败时回退到人工判断（熔断机制）

提示工程：优化系统提示词

核心对象是系统提示词（System Prompt），定义了 Agent 的身份、行为规则、约束条件和工作流程

语气与风格：系统提示词的”人格”

要求AI简洁回答，具体要求（不要解释为什么不能做，会让AI陷入冗长的自我辩护），具体提醒（比如使用大写字母等），但过度使用会导致效果被稀释，应保留给真正关键的约束

结构化提示：系统提示词的”格式”

现代大语言模型对结构化输入展现出显著的敏感性，这源于训练数据中包含大量的结构化内容。

XML 标签的使用遵循层次化原则，其标签名称本身就携带语义信息——<working_directory> 能立即告诉模型这是工作目录信息，而纯文本格式”当前目录：/Users/project/src”则需要模型做额外的思考来理解冒号前后的关系。

Markdown 在保持可读性的同时提供了轻量级的结构，特别适合组织层次化的指令和信息。XML 和 Markdown协同配合，创造了一种双层结构：XML 负责机器可解析的精确语义，Markdown 负责人机共读的组织逻辑。

注：能用Markdown文件的尽可能使用Markdown文件类型，到最后一步再指定生成的文件类型。

动态提示词与 Agent Skills

全部塞进一个提示词会造成：浪费 token、注意力被稀释

Agent Skills 的核心思想是将 Agent 的能力模块化为独立的、可按需加载的知识包。

  1. 第一层（元数据）：每个 Skill 必须包含一个 SKILL.md 文件，开头是 YAML frontmatter（即文件顶部用 --- 分隔的元数据块，类似书籍的版权页），包含 name 和 description 两个字段。Agent 框架在启动时扫描所有已安装的 Skill，将它们的 name 和 description（仅占数百个 token）注入到对话上下文中（注入位置的设计权衡见下一小节），使 Agent 在不消耗大量上下文的前提下知晓自己拥有哪些专业能力。
  2. 第二层（核心流程）：当 Agent 判断某个任务需要特定的 Skill 时，通过专用的 Skill 工具加载完整的 SKILL.md，内容作为 tool result 出现在对话历史中。
  3. 第三层（细则）：通过文件引用深入到更详细的子文档。Agent 会根据具体的需求选择性地深入阅读相关的子文档。

Skill 内容放在上下文的什么位置：

  • 方式一：注入系统提示词（system 消息）：Skill 的执行效果最好。但问题在于：每次加载新的 Skill 都会改变 system 消息的内容，导致 KV Cache 前缀失效。如果 Agent 频繁切换 Skill（比如一个任务需要先用搜索 Skill，再用文档 Skill），缓存会反复失效，延迟和成本显著增加。
  • 方式二：作为普通文件读取：内容出现在上下文中间，对模型的指令遵循（instruction following）能力提出了更高要求。
  • 方式三（生产实现）：元数据注入上下文末尾，完整内容通过专用工具按需加载。

Skills 机制对 KV Cache 极为友好。

上下文压缩策略

压缩动机：解决长度约束和成本约束、提升思考质量——总结后的知识比原始形式更利于模型使用

上下文学习的内部机制：检索而非推理

假设上下文中包含一段宠物店的巡查记录：笼子 1：黑猫。笼子 2：白猫。笼子 3：黑猫。笼子 4：黑猫。笼子 5：白猫。⋯⋯（共 100 个笼子，其中 90 只黑猫、10 只白猫）

当你问模型”黑猫和白猫各有多少只？”时，如果不启用思维链（Thinking），模型很难直接给出正确答案——因为注意力机制擅长的是查找（”笼子 37 里是什么猫？”），而不是统计归纳（”总共有多少只黑猫？”）。后者需要遍历所有记录并维护计数状态，这本质上是思考而非检索。

如果启用思维链，模型可以通过逐个数数来得到正确答案——但代价是每一次被问到这个问题，都需要重新从头数一遍，产生大量的思考 token。

而如果我们提前做一次总结，在上下文中直接写入”当前统计：黑猫 90 只，白猫 10 只”，模型就能立即检索到这个结论，无需重新思考。这就是压缩的第二个价值：把需要思考才能得到的结论变成可以直接检索的知识。

压缩策略的设计原则

  1. 信息价值的非均匀分布
  2. 语义完整性
  3. 任务相关性
  4. 压缩即理解
